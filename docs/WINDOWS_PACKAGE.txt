TTalk Windows 0.4 — version candidate, Windows 10/11 x64

Fermer les anciennes versions avant de lancer cette préversion. Ne pas utiliser
0.3.6 et 0.4 sur le même profil en même temps.

1. Extraire TOUT le ZIP et lancer ttalk.exe. Garder les DLL et data à ses côtés.
2. Créer ou saisir son PIN (4 à 12 chiffres).
3. Ouvrir Configurer le serveur et saisir l’adresse HTTPS du relais hébergé.
   Les deux PC doivent utiliser la même adresse. Aucune recompilation nécessaire.
4. Choisir Mon nom, puis échanger un code d’appairage et comparer les numéros de sécurité.

Un PC utilisateur n’a pas besoin de rester allumé : le relais est hébergé en
permanence. Il reste à créer l’hébergement si vous n’en avez pas encore.
Guide : https://github.com/btalal/TTalk/blob/vibe/talmessenger-e2e-5e4935/server/README.md
Node.js n’est nécessaire sur le PC que pour les tests avec un relais local.

Les contacts et les clés persistent après redémarrage. Les envois sans réseau
restent dans le coffre. Le serveur conserve les messages chiffrés en attente
pendant 7 jours maximum. Une horloge indique un envoi encore en attente.

Migration : conserver les données Windows et le PIN. Les contacts sont convertis
automatiquement. Les groupes de 0.3.6 restent consultables mais doivent être recréés.
Les deux PC et le serveur doivent utiliser la nouvelle version.

Les fichiers reçus sont enregistrés en clair dans Documents/ttalk_files après
déchiffrement. Protéger le compte Windows. Ne pas effacer les clés de l’application.
Le package n’est pas signé Authenticode ; une somme SHA256 accompagne le ZIP.
Cette version candidate ne vaut pas validation d’un hébergement encore inexistant.
